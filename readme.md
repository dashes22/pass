# Система авторизации
Учебный проект. Регистрация и вход пользователей с проверкой надёжности пароля и защитой от подбора.

## Как запустить
1. Установить зависимости:
   npm install
2. Запустить сервер:
   node server.js
3. Открыть в браузере:
   http://localhost:3000

## Описание файлов проекта
### src/db.js
Подключение к базе данных SQLite. Открывает файл `pass.db` в корне проекта, создаёт таблицу `users`, если её ещё нет. Экспортирует объект `db`, который используется в других модулях для запросов.

### src/validate.js
Валидация пароля и логина. Экспортирует:

- `validatePassword(password)` - асинхронная функция. Проверяет длину, наличие заглавной и строчной буквы, цифры, спецсимвола и отсутствие пароля в списке частых. Возвращает объект `{ valid, message }`.
- `validateLogin(login)` - синхронная функция. Проверяет, что логин не пустой и не короче трёх символов.
- `isCommonPassword(password)` - обёртка над библиотекой `common-password`. Возвращает `true`, если пароль в списке частых.

### src/block.js
Логика блокировки после нескольких неудачных попыток входа. Хранит данные в памяти (объект `failedAttempts`). Экспортирует:

- `checkBlock(login)` - возвращает остаток блокировки в секундах или 0, если блокировки нет.
- `addFailedAttempt(login)` - регистрирует неудачную попытку и, если нужно, ставит блокировку.
- `getBlockTimeRemaining(login)` - то же, что `checkBlock`, но в миллисекундах.
- `resetAttempts(login)` - сбрасывает счётчик попыток (используется при успешном входе).
- `failedAttempts` - сам объект с данными попыток.

### src/crypto.js
Хеширование паролей. Экспортирует:

- `generatePepper()` - создаёт случайную строку из 32 байт (pepper). Хранится в базе рядом с хешем.
- `hashPassword(password, pepper)` - хеширует пароль вместе с pepper через argon2id.
- `verifyPassword(hash, password, pepper)` - сравнивает пароль с сохранённым хешем.

### src/auth.js
Основная логика: регистрация и вход. Не знает про HTTP, работает с данными напрямую. Экспортирует:

- `registerUser(login, password)` - проверяет логин, валидирует пароль, хеширует, сохраняет в базу. Возвращает `{ success, message }`.
- `loginUser(login, password)` - проверяет блокировку, ищет пользователя, сравнивает пароль. Возвращает `{ success, message, login }`.

### src/routes.js
HTTP-эндпоинты Express. Тонкий слой - принимает запросы, вызывает функции из `auth.js`, отправляет JSON обратно. Три эндпоинта:

- `POST /check-login` - проверяет, свободен ли логин.
- `POST /register` - регистрирует нового пользователя.
- `POST /login` - проверяет логин и пароль для входа.

### server.js
Точка входа. Создаёт Express-приложение, подключает middleware (`cors`, `express.json`, статику), подключает роуты из `src/routes.js` и запускает сервер на порту 3000.

### index.html
Страница с формой. Содержит:

- поле для ввода логина
- поле для ввода пароля
- подсказку о требованиях к паролю
- скрытое поле «Повторите пароль» (появляется при регистрации)
- кнопки «Зарегистрироваться» и «Войти»
- блок для вывода сообщений

### style.css
Стили страницы. Оформляет карточку по центру, поля ввода, кнопки, блок с сообщениями. Адаптируется под узкие экраны.

### script.js
Клиентская часть. Работает в браузере и общается с сервером.

Что делает:
- читает то, что пользователь ввёл в поля
- отправляет запросы на сервер через fetch
- показывает результат: успех или ошибку
- прячет и показывает поле «Повторите пароль»
- проверяет, что логин свободен, перед тем как просить повтор пароля
- обрабатывает нажатие Enter в полях
- очищает поля после успешной регистрации или входа

### test.js
Юнит-тесты на встроенном модуле `node:test`. Импортирует функции из `src/` и проверяет их работу.
Запуск:
node test.js
Или:
npm test

Что проверяет:
- валидация пароля (длина, заглавная буква, строчная буква, цифра, спецсимвол, частые пароли)
- валидация логина (пустой, из пробелов, короткий, нормальный)
- логика блокировки (10 секунд, 30 секунд, 5 минут, удвоение, максимум 1 час)

### package.json

- `npm start` — запустить сервер
- `npm run dev` — запустить сервер с автоперезагрузкой через nodemon
- `npm test` — запустить тесты
- `npm run test:watch` — запустить тесты с автоперезагрузкой

### pass.db
Файл базы данных SQLite. В нём хранятся данные.

Таблица users:
- id - номер пользователя
- login - логин
- password - хеш пароля
- pepper - случайная строка для усиления хеша
- created_at - дата регистрации

## Требования к паролю
Пароль должен:
- быть не короче 8 символов
- содержать хотя бы одну заглавную букву
- содержать хотя бы одну строчную букву
- содержать хотя бы одну цифру
- содержать хотя бы один специальный символ (!@#$%^&* и другие)
- не быть в списке частых паролей

## Блокировка при подборе пароля
Если пользователь несколько раз вводит неправильный пароль, вход временно блокируется:

- 1-я неудачная попытка - 10 секунд
- 2-я - 30 секунд
- 3-я - 5 минут
- 4-я и дальше - каждый раз удваивается, но не больше 1 часа

Если после последней попытки прошло 5 минут, счётчик сбрасывается.

## Параметры хеширования
Пароли хешируются через argon2id со следующими параметрами:
- memoryCost: 65536 KiB (64 MiB)
- timeCost: 3
- parallelism: 1
Время хеширования на тестах - около 105 мс.

Проверить у себя:
npm run benchmark

## Безопасность
- Пароли хранятся в виде хешей argon2id, восстановить исходный пароль невозможно.
- Перед хешированием к паролю добавляется случайный pepper - своя соль для каждого пользователя.
- Запросы к базе используют подготовленные выражения (`?`), что защищает от SQL-инъекций.
- После нескольких неудачных попыток вход блокируется на время.
